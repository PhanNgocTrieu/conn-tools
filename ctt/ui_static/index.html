Chuẩn bị

Chạy lần lượt các bước sau. Bước 1 không cần DUT.

  1. Mục "Trạng thái firmware" cho biết usb-daemon, bt-daemon và wifi-daemon có đang chạy không, WiFi đang ở mode nào, BT đã bond bao nhiêu thiết bị (tối đa 5), cổng USB đang là host hay device.
  2. Trước mỗi test, CTT tự cảnh báo (dòng màu vàng) nếu test sắp giành tài nguyên với một daemon.

Đo throughput / latency

Mặc định server chạy trên DUT: tx = PC→DUT, rx = DUT→PC, bidir = cả hai chiều, echo = RTT.

Tiêu chí PASS

Chạy profile YAML

Một profile gồm nhiều test kèm tiêu chí PASS. Xem danh sách test trong profile trước khi chạy.

Mode WiFi của DUT (wifi-daemon)

Trên head unit, DUT thường ở chế độ AP (hostapd trên wlan0). Đổi mode bằng Manager.SetMode.

Đo WiFi khi DUT là AP

  1. Bấm "Xem SSID / passphrase / kênh", rồi cho PC (hoặc USB WiFi dongle gắn vào WSL) kết nối vào AP đó.
  2. Ở ô DUT phía trên, nhập IP của DUT trên mạng AP (đi qua WiFi), hoặc giữ SSH qua Ethernet và nhập endpoint là IP AP.
  3. Sang tab Throughput, bấm preset "WiFi TCP". Trong ô "Ghi WiFi link" nhập wlan0 để ghi RSSI và bitrate của client, đo từ phía DUT.

Pairing

PC (dongle) chủ động pair tới DUT. Khi DUT chạy bt-daemon, chọn bm (hoặc auto): CTT sẽ xác nhận pairing qua D-Bus của bt-daemon thay vì đăng ký agent riêng.

Bond trên DUT

bt-daemon giữ tối đa 5 bond. Khi đã đủ 5, các lần pair mới bị lỗi CapacityReached.

Gadget USB trên DUT

Lên: dừng usb-daemon, chuyển dwc2_drdmode sang device, rồi tạo gadget CTT. Xuống: trả cổng về host và chạy lại usb-daemon. Luôn bấm Xuống sau khi test xong.

MFi coprocessor (I2C)

Trên board vendor: /dev/i2c-1, địa chỉ 0x10. File example chạy trên bus giả lập; với chip thật, copy thành configs/mfi_cp.private.yaml rồi điền register map.
